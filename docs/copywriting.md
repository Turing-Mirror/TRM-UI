# 桌面软件文案原则与廉耻表

## 在 TRM UI 中使用

本规范用于新增或修改界面标签、设置说明、提示、状态、错误信息、帮助内容及其多语言译文。已经审阅确认的表述直接沿用；对接代码时只调整确有变化的键名、占位符及功能对应关系。

参数范围、默认值、耗时、隐私处理、菜单入口和视觉行为均以当前实现为依据。表中的纸张配色、赤陶强调色和卡片上浮属于文体示例；TRM UI 的视觉与交互遵循 [交互约定](patterns.md)、[设计规范](tokens.md) 和当前源码。

开发者文档、组件画廊中的代码示例及诊断详情可以保留必要的 API、CSS 变量、脚本名、命令和路径。普通用户提示应说明实际问题与操作方法，诊断信息继续保留排查所需的细节。

修改语言包前核对调用位置，保持八种语言的键名与占位符一致，并保留算法名、协议名和可执行命令。修改完成后运行现有的 `npm run check:i18n`。该检查验证结构、占位符与引用，文体和功能含义仍需逐条审阅。

以下原则与对照表沿用提供的规范正文。

## 一、核心原则

1. **端庄克制是常态**：界面标签、设置说明、悬停提示、状态栏、报错弹窗与帮助文档统一使用完整、平实、克制的现代书面语。只陈述客观事实、参数作用与操作后果，不替用户抒情、不讲俏皮黑话、不强打比方、不写防御性免责口水话。
2. **隐藏底层研发实现**：面向普通用户的界面只谈概念与功能，不暴露内部进程名、脚本文件名、代码枚举前缀或研发俚语（如 `worker`、`render`、`落地`、`热更`、`写死`）。
3. **该亲切时自然亲切，不写公文腔**：里程碑致谢、求关注弹窗、彩蛋文本与新手引流钩子保持自然真诚的语气，不写成冰冷的公文通知。
4. **测试数据与生产语言包隔离**：正式语言包（`i18n/locales/*.json`）只收录真实界面文案，单元测试假数据必须保留在测试文件内部。
5. **多语言翻译遵循领域术语**：保留专有算法、协议与命令原名，使用软件工程领域的地道母语词汇，禁止脱离上下文逐字死译。
